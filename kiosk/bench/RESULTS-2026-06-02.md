## Findings (and the fixes applied on this branch)

### 1. This RTL2838 drops off the USB bus after repeated open/reset cycles
Cold, it enumerates and streams fine. After several rapid `rtl_fm` start/stop/reset
cycles (as a bench loop produces) it disappears from `lsusb` entirely and needs a
physical replug; a software unbind/bind does **not** re-enumerate it. This is a
known trait of cheap RTL dongles, not a software bug — but it makes an automated
full-bench loop unreliable. *Mitigation in code:* the engine now surfaces the
device-gone state as a `NO_DEVICE` error event (finding 3) instead of silently
spinning.

### 2. HDMI audio exposes no `amixer` control; headless `aplay` to default fails
Neither HDMI card (0 `vc4hdmi0`, 1 `vc4hdmi1`) has any `amixer` simple control —
only the headphone jack (card 2) has a `PCM` control. The engine called
`amixer -c 0 sset Master …`, which can't succeed on HDMI here. Separately,
`aplay` to the default device failed headless with `audio open error: Unknown
error 524` (no audio session). *Fix on this branch:* `aplay` is now pointed at
the configured `audio.sink` via `-D`, and `amixer` volume/mute degrade to a safe
no-op when no mixer control exists (instead of erroring / risking the boot chain).
Name→card-index mapping and control discovery remain a documented limitation.

### 3. Squelch config default sat on the noise floor
Default `squelchLevel: 150` ≈ the measured noise floor → constant false
squelch-opens. *Fix on this branch:* default raised to **1800** (clears noise
~150–1436, well below signal ~2900). Operators can still set any value.

### 4. `rtl_fm` stderr was discarded
The engine spawned `rtl_fm` with stderr ignored, so "No supported devices found"
(the exact symptom of finding 1) produced no useful signal. *Fix on this branch:*
the engine captures rtl_fm stderr and, on unexpected exit, emits a `NO_DEVICE`
error (dongle missing/wedged) vs a generic `RTL_EXITED`, including the captured
reason in the message.
